# Board build and runtime loading

Source the jtcores root `setprj.sh`, then run `board/build.sh NEW_BUILD_DIRECTORY`. The directory must not exist. Builds target5CSEBA6U19C8 with a100MHz HPS user0 root and an explicitly constrained, globally routed50MHz divide-by-two for the whole controller and all four lanes; inspect actual post-fit setup/hold timing and resource use before operating at that rate. The initial direct100MHz build failed setup and is not approved for operation. Successful compilation alone does not certify timing. No external clock or Qsys/DDR changes are introduced.

The build hashes actual production `hdl/*.v`, wrapper `rtl/*.v` and JTFRAME RAM helpers, plus build/SDC/overlay sources. It emits `build.vh` with `JT51_FPGA_SOURCE_HASH256`, `source-hash.txt`, input manifests and uniquely named `c96-jt51.rbf`/`c96-jt51.dtbo`. Inputs are rechecked after compilation; a source change fails the build. Keep output artifacts outside the repository. No simulation/debug macros are enabled.

Runtime loading is an explicit separate ROOT action on Chameleon96. Put the new firmware files under `/lib/firmware/`; put `c96-jt51` and its pinned `source-hash.txt` beside `load-fpga.sh`. `load-fpga.sh jt51` validates board/USB/user0, obtains the existing capture lock, schedules recovery, quiesces fabric drivers and uses configfs overlay `path`. The new probe validates protocol0x965101 and all256 source-hash bits before success. `load-fpga.sh jt51 EXPECTED_HASH_FILE` can name the expected hash explicitly; otherwise it uses `source-hash.txt` beside the tool. Pins E5/F5/A6/A5 remain input-only; the top must retain those declarations. Capture firmware/tool/stock boot files are never overwritten.

`load-fpga.sh yamaha104` explicitly restores separately retained `/lib/firmware/c96-yamaha104.{rbf,dtbo}` and validates with a separately retained `c96-capture104` beside the loader. `original` uses separately verified `c96-original` images; neither image is generated or replaced here. Preserve existing current-capture/source hashes and original recovery assets before first use. Reboot uses unchanged stock boot files. USB, not Wi-Fi/display, is the recovery transport.

Loading requires the documented old-kernel configfs `path` workaround. Never write the overlay's `dtbo` attribute. The recovery timer is cancelled only after manager state and design-specific probe succeed. Programming is not part of build.sh.
